# LLM Request Classifier

Небольшой backend-сервис на FastAPI: принимает текст обращения клиента, классифицирует его через Claude API и возвращает категорию, приоритет и черновик ответа.

## О проекте

Типовая задача службы поддержки — прочитать входящее обращение, понять, к чему оно относится, и решить, насколько срочно на него реагировать. Этот сервис автоматизирует первый шаг: текст на входе, структурированный результат на выходе, готовый использовать дальше — хоть в интерфейсе поддержки, хоть в качестве шага в более крупном воркфлоу (например, вызываться из n8n вместо прямого обращения к LLM API).

## Возможности

- `POST /classify` — классификация текста: категория, приоритет, краткое summary, черновик ответа
- `GET /health` — проверка живости сервиса
- Автоматическая Swagger-документация на `/docs`
- Валидация входных данных (Pydantic)
- Обработка ошибок LLM API отдельно от ошибок валидации (503 при недоступности LLM, 502 при невалидном ответе LLM, 422 при некорректном входе)
- Повторная попытка запроса к LLM, если модель вернула не-JSON ответ

## Как это работает

Клиент → `POST /classify` с текстом → сервис отправляет текст в Claude с системным промптом, требующим строго структурированный JSON → парсит и валидирует ответ через Pydantic → возвращает клиенту.

## Технологии

- Python 3.12
- FastAPI
- Pydantic
- Anthropic Python SDK (Claude API)
- pytest — тесты с мокнутым LLM-клиентом (не требуют реального API-ключа)

## Установка

```bash
git clone https://github.com/<your-username>/llm-classifier-service.git
cd llm-classifier-service

python -m venv venv
venv\Scripts\activate       # Windows
# source venv/bin/activate  # Linux/macOS

pip install -r requirements.txt

cp .env.example .env
# впиши свой ANTHROPIC_API_KEY в .env
```

## Использование

Локально:
```bash
uvicorn app.main:app --reload
```
Открой http://localhost:8000/docs — там интерактивная документация, можно сразу протестировать `/classify`.

Через curl:
```bash
curl -X POST http://localhost:8000/classify \
  -H "Content-Type: application/json" \
  -d '{"text": "Здравствуйте, третий день не могу оплатить заказ, помогите разобраться"}'
```

Через Docker:
```bash
docker build -t llm-classifier .
docker run -p 8000:8000 --env-file .env llm-classifier
```

## Тесты

```bash
pytest
```
Все тесты мокают вызов LLM — реальный API-ключ для тестов не нужен.

## Технические особенности

- **Разделение ответственности**: `main.py` отвечает только за HTTP-слой, вся логика общения с LLM — в `llm_client.py`, схемы данных — отдельно в `schemas.py`. Это упрощает тестирование и замену LLM-провайдера в будущем.
- **Обработка невалидного JSON от LLM**: модели иногда оборачивают ответ в markdown-разметку или добавляют лишний текст — `llm_client.py` это чистит и делает повторную попытку, если распарсить всё равно не удалось.
- **Разные коды ошибок для разных случаев отказа**: 422 (некорректный вход), 503 (LLM недоступен), 502 (LLM ответил, но не тем, что ожидалось) — а не единый "500 Internal Server Error" на всё подряд.

## Ограничения

- Промпт и категории сейчас захардкожены под кейс "обращения в поддержку" — для другого домена промпт в `llm_client.py` нужно будет переписать под свои категории.
- Нет персистентного хранения истории классификаций (сервис синхронный, без базы данных) — по назначению это классификатор-утилита, а не полноценная CRM.
- Нет аутентификации на эндпоинтах — для реального продакшена нужно добавить API-ключ или другой механизм авторизации.

## Дальнейшее развитие

Идеи на будущее, не реализовано:

- добавить эндпоинт для батч-классификации нескольких обращений за один запрос;
- вынести промпт и список категорий в конфиг, чтобы не редактировать код под каждый новый домен;
- добавить аутентификацию по API-ключу;
- логировать классификации в базу для последующего анализа качества.
